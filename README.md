# law_AI_FE

> **법안잇다** — 유사 법률안을 찾고, 연결하다.
> **유사 법률안 검색 · 비교 · 요약 서비스**의 프론트엔드입니다.
> 열린국회정보(22대 발의법률안) 데이터를 서버(BE)가 가공해서 내려주면, 이 앱이 검색 화면과 비교 화면으로 보여줍니다.

- 서버(BE) 레포: _(링크 추가)_
- 데이터 출처: 열린국회정보 Open API (발의법률안 목록, 법률안 제안이유 및 주요내용)
- AI 분석(유사도, 요약, 비교)은 **서버에서** 수행하고, 이 앱은 결과를 보여주는 역할만 합니다.

---

## 1. 서비스 소개

국회에는 같은 법을 고치거나 비슷한 내용을 담은 법률안이 매우 많습니다. 제목만 봐서는 무엇이 다른지 알기 어렵습니다.
이 서비스는 **일상적인 키워드로 관련 법률안을 찾고, AI 요약으로 내용을 빠르게 파악하고, 두 법률안을 골라 차이점을 비교**할 수 있게 합니다.

> 예) 사용자가 `월세 지원금`을 검색 → 관련 법률안이 관련도 순으로 나열 → 궁금한 법률안만 `AI 요약 확인하기`로 요약 확인 → 마음에 드는 두 법률안을 선택 → 공통점과 차이점 확인

## 2. 핵심 기능

### 2-1. 키워드 검색

| 항목 | 내용 |
|---|---|
| 입력 | 자연스러운 키워드 한 줄 (예: `월세 지원금`, `전세사기`, `청년 교통혜택`) |
| 동작 | 검색어를 서버에 전달하고, 결과를 받아 목록으로 표시 |
| 보조 기능 | 예시 검색어 칩(클릭하면 바로 검색), 최근 검색어(선택 사항) |
| 상태 처리 | 로딩 / 결과 없음 / 오류 / 빈 입력 |

- 검색 방식(키워드 매칭, 유의어 확장 등)은 서버가 정합니다. 프론트는 검색어를 가공하지 않고 그대로 보냅니다.
- 법률안 이름이나 본문에 해당 단어가 없으면 검색되지 않을 수 있습니다. 결과가 적으면 "다른 키워드로 검색해 보세요" 안내를 보여줍니다.

### 2-2. 검색 결과 목록 (관련도 순 + AI 요약 버튼)

- 서버가 준 **관련도(score) 순서 그대로** 정렬해서 보여줍니다.
- 법률안 카드 한 장에 들어가는 정보

| 표시 항목 | 설명 |
|---|---|
| 법안명 | 클릭하면 원문 링크로 이동 (새 탭) |
| 소관위원회 · 발의일 · 의안번호 | 메타 정보 |
| 처리 상태 뱃지 | 본회의 통과 / 대안에 반영(폐기) / 심사 중 (아래 [상태 표시 규칙](#5-ui-규칙) 참고) |
| 매칭된 키워드 | 검색어와 맞은 단어를 강조 표시 |
| **AI 요약 확인하기** | 버튼을 누른 법안만 서버에 요약을 요청해 카드 안에 보여줌 |
| 비교에 담기 | 체크하면 비교 바구니에 추가 (최대 2건) |

- **AI 요약은 미리 만들지 않습니다.** 검색 결과마다 요약을 만들면 AI 토큰이 낭비되므로, 사용자가 `AI 요약 확인하기`를 누른 법안만 요약을 요청합니다([8-2](#8-2-법안-요약-버튼을-눌렀을-때만)).
- 한 번 받은 요약은 다시 요청하지 않습니다. 다른 화면에 다녀와도 그대로 보입니다(새로고침 전까지).
- 요약을 만드는 동안 버튼에 "요약하는 중…"을 표시합니다.
- AI 요약이 없으면(`summary: null`, 원문 없음 등) "요약을 준비하지 못했어요. 원문 링크를 확인하세요"를 표시합니다.
- 요청 자체가 실패하면 "요약을 불러오지 못했어요"와 `다시 시도` 버튼을 표시합니다.
- 요약 아래에 "AI가 생성한 요약이며 원문과 다를 수 있습니다." 안내를 표시합니다.
- 비교 화면의 두 법안 요약은 비교 API가 함께 내려주므로 버튼 없이 바로 보여줍니다.

### 2-3. 두 법률안 비교

1. 검색 결과에서 법률안 **2건**을 선택하면 화면 아래에 비교 바(`비교할 법안 2/2 · 비교하기`)가 나타납니다.
2. `비교하기`를 누르면 비교 화면(`/compare`)으로 이동합니다.
3. 비교 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | 법률안 A, B의 이름 · 소관위 · 상태 · 원문 링크 · 각각의 AI 요약 |
| 비슷한 내용 | 두 법률안에서 겹치는 문장 |
| **차이점** | A에만 있는 내용 / B에만 있는 내용 |
| **AI 비교 요약** | 공통점과 차이점을 자연어로 설명한 글 (서버가 AI를 쓸 수 없으면 숨김) |

- 비교 바구니는 다시 검색해도 비워지지 않습니다. **서로 다른 키워드로 찾은 법안끼리도** 비교할 수 있습니다.
- 비교 화면 주소는 `/compare?a=<의안번호>&b=<의안번호>` 형태로 만들어서, **링크만 공유해도 같은 비교 결과**를 볼 수 있게 합니다.
- 비교 결과는 생성에 시간이 걸릴 수 있으니 로딩 상태(스켈레톤)를 보여줍니다.

### 2-4. 법안 저장

- 법률안 카드의 `저장` 버튼으로 법안을 저장하고, 사이드바 `저장한 법안`(`/saved`)에서 모아 봅니다.
- 저장한 법안 화면에서도 2건을 골라 비교할 수 있습니다.
- 로그인 기능이 없으므로 **브라우저(localStorage)에만** 보관합니다. 다른 기기·브라우저와 공유되지 않습니다. 서버 저장이 필요해지면 BE와 API를 협의합니다.

## 5. UI 규칙

### 상태 표시 규칙

법안의 처리결과는 서버가 `status` 값으로 내려줍니다.

| `status` | 화면 표기 | 의미 |
|---|---|---|
| `PASSED` | 본회의 통과 | 본회의에서 원안가결 또는 수정가결된 법안. 시행 시기는 별도이므로 원문 링크에서 확인 |
| `MERGED` | 대안에 반영(폐기) | 위원회 대안에 내용이 흡수되고 이 법안은 폐기됨. **통과가 아님**. 대안의 처리 여부는 원문 링크에서 확인 |
| `REVIEW` | 심사 중 | 국회에서 심사 중이며 통과 여부 미정 |
| `OTHER` | 기타 | 그 외 처리결과 (철회 등) |

> `MERGED`를 "통과"로 표시하면 사용자가 오해하므로 **절대 같은 색·같은 문구로 표시하지 않습니다.**

### 필수 고지 문구

- 모든 AI 요약/비교 영역: **"AI가 생성한 요약이며 원문과 다를 수 있습니다."**
- 비교 화면과 푸터: **"법률 자문이 아닌 정보 안내입니다. 정확한 내용은 원문을 확인하세요."**
- 모든 법률안 카드에 **원문 링크**를 표시합니다.

### 공통

- 모바일 화면(폭 360px 이상)에서 깨지지 않게 만듭니다.
- 버튼, 입력창은 키보드로 조작할 수 있어야 합니다.

## 6. 시작하기

### 준비물

- Node.js (LTS), npm
- Git

### 설치 및 실행

```bash
git clone <이 레포 주소>
cd law_AI_FE
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`이 열리면 성공입니다.

### UI 미리보기

현재 화면은 `src/api/mock.js`의 예시 데이터로 동작하며 실제 서버에는 연결하지 않습니다.

- 첫 화면은 로고·검색창과 기능 소개 카드 3개입니다. 검색하면 카드 자리에 검색 결과가 표시됩니다. `추천 키워드` 카드의 키워드를 누르면 바로 검색됩니다.
- 검색 버튼 또는 엔터키로 예시 데이터를 검색합니다. 검색어 중 한 단어라도 포함된 데이터를 표시하며 기존 순서를 유지합니다. 실제 검색 방식은 서버 연결 시 교체합니다.
- `월세 지원금`으로 법안 카드 3개를 확인할 수 있습니다. 카드의 `AI 요약 확인하기`를 누르면 잠시 뒤 예시 요약이 나타나고, `조세특례제한법` 카드에서는 요약이 없는 경우를 확인할 수 있습니다. `전세사기`로 검색 결과가 없는 화면을 확인할 수 있습니다.
- 사이드바 로고나 검색 결과 화면의 `법안잇다` 제목을 누르면 첫 화면(기능 소개)으로 돌아갑니다. 비교 바구니와 저장 목록은 유지됩니다.
- 비교 체크박스는 최대 2개를 선택할 수 있습니다. 다른 키워드로 다시 검색해도 담은 법안은 유지됩니다. 예: `세액공제`로 검색해 `조세특례제한법`을 담고, `청년주거`로 검색해 `청년주거지원 특별법안`을 담기. 선택 해제는 체크박스 또는 하단 비교 바구니에서 할 수 있습니다.
- 비교 버튼으로 `/compare?a=...&b=...`에 이동합니다. 검색 화면으로 돌아와도 검색어와 선택한 법안은 유지됩니다. 새로고침하면 검색·선택 상태는 초기화되지만, 비교 주소는 주소의 의안번호로 다시 표시됩니다.
- 비교 예시는 의안번호 `2200001`과 `2200003` 조합에 준비되어 있습니다. 다른 조합은 비교 데이터가 준비되지 않았다는 안내를 표시합니다.
- 저장한 법안 화면은 `src/pages/SavedPage.jsx`, 하단 비교 바구니는 `src/components/CompareTray.jsx`,
- 사이드바(로고·메뉴)는 `src/App.jsx`, 로고는 `src/components/Logo.jsx`, 검색 UI와 기능 소개 카드는 `src/pages/SearchPage.jsx`, 카드와 상태 배지는 `src/components/BillCard.jsx`, 비교 UI는 `src/pages/ComparePage.jsx`에서 수정합니다. 화면 스타일은 `src/App.css`에 있습니다.

클라이언트 빌드와 기본 렌더링을 검증했습니다. 자동 브라우저에서 로컬 서버에 연결할 수 없어 클릭 동작과 360px 모바일 화면의 직접 확인은 남아 있습니다.

### 자주 쓰는 명령

실제 스크립트 목록은 `package.json`의 `scripts`를 확인하세요.

## 7. 서버(BE) 연결

프론트는 `/api/...`로만 서버를 호출합니다. 개발 중에는 Vite 프록시로 서버(`localhost:8000`)에 전달합니다.

`vite.config.js`의 `defineConfig` 안에 아래를 추가합니다. (아직 적용 전이면 이 단계에서 추가)

```js
server: { proxy: { '/api': 'http://localhost:8000' } },
```

설정을 바꾼 뒤에는 `npm run dev`를 껐다가 다시 켭니다.

서버가 준비되기 전에는 `src/api/`의 **가짜 데이터(mock)** 로 화면을 먼저 만듭니다. 서버가 완성되면 mock 호출을 실제 호출로 바꿉니다.

## 8. API 명세 (초안, BE와 협의 후 확정)

> 아래는 프론트가 필요로 하는 형태의 **제안**입니다. 값은 모두 예시이며 실제 법안 정보가 아닙니다.
> 필드가 바뀌면 이 문서를 먼저 수정하고 팀에 공유하세요.

### 8-1. 검색

`GET /api/search?q={검색어}&limit=10`

```json
{
  "query": "월세 지원금",
  "total": 1,
  "results": [
    {
      "bill_no": "0000001",
      "bill_name": "OO법 일부개정법률안",
      "committee": "OO위원회",
      "propose_date": "2026-10-20",
      "status": "REVIEW",
      "link": "https://example.com/bill/0000001",
      "score": 0.82,
      "matched_keywords": ["월세", "세액공제"]
    }
  ]
}
```

- `results`는 **관련도 순으로 정렬**되어 옵니다. 프론트는 순서를 바꾸지 않습니다.
- 검색 결과에는 AI 요약(`summary`)을 넣지 않습니다. 요약은 아래 8-2로 따로 요청합니다.

### 8-2. 법안 요약 (버튼을 눌렀을 때만)

`GET /api/bills/{bill_no}/summary`

```json
{ "bill_no": "0000001", "summary": "AI가 요약한 내용 (없으면 null)" }
```

- 사용자가 카드의 `AI 요약 확인하기`를 눌렀을 때만 호출합니다. AI 토큰을 아끼기 위해서입니다.
- 서버도 의안번호별로 만든 요약을 저장해 두고, 같은 법안을 다시 요청하면 AI를 다시 부르지 않고 저장한 요약을 돌려주는 것을 권장합니다.
- AI가 요약을 만들지 못하면 `summary: null`로 보냅니다. 의안번호가 없으면 404와 8-4 형식의 오류를 보냅니다.

### 8-3. 비교

`POST /api/compare`

요청:
```json
{ "a": "0000001", "b": "0000002" }
```

응답:
```json
{
  "a": { "bill_no": "0000001", "bill_name": "...", "committee": "...", "status": "REVIEW", "link": "...", "summary": "..." },
  "b": { "bill_no": "0000002", "bill_name": "...", "committee": "...", "status": "MERGED", "link": "...", "summary": "..." },
  "similarity": 0.71,
  "common": ["두 법안에서 비슷한 문장"],
  "only_a": ["A에만 있는 문장"],
  "only_b": ["B에만 있는 문장"],
  "ai_summary": "공통점·차이점 설명 (AI를 쓸 수 없으면 null)"
}
```

### 8-4. 오류 응답

```json
{ "error": { "code": "NOT_FOUND", "message": "사람이 읽을 수 있는 설명" } }
```

- 프론트는 HTTP 상태코드와 `error.message`로 오류 화면을 보여줍니다.

### 8-5. 값이 비어 있을 때 프론트 처리

| 값 | 처리 |
|---|---|
| `summary: null` | "요약을 준비하지 못했어요. 원문 링크를 확인하세요" |
| 요약 요청 실패 (8-2) | "요약을 불러오지 못했어요" + `다시 시도` 버튼 |
| `ai_summary: null` | AI 비교 요약 영역을 숨기고, 문장 비교(비슷한 내용 / 각각에만 있는 내용)만 표시 |
| `results: []` | "검색 결과가 없어요. 다른 키워드로 검색해 보세요" |

## 9. 폴더 구조 (권장)

```
src/
├─ api/                 서버 호출 함수, mock 데이터
│  ├─ client.js         fetch 공통 처리 (오류 처리 포함)
│  ├─ bills.js          search, compare 호출
│  └─ mock.js           서버 없이 개발할 때 쓰는 가짜 데이터
├─ pages/
│  ├─ SearchPage.jsx    검색 화면 (/)
│  └─ ComparePage.jsx   비교 화면 (/compare)
├─ components/
│  ├─ SearchBar.jsx     입력창 + 예시 검색어 칩
│  ├─ BillCard.jsx      법률안 카드 (요약, 비교 체크 포함)
│  ├─ StatusBadge.jsx   처리 상태 뱃지
│  ├─ CompareTray.jsx   하단 비교 바구니
│  ├─ AiNotice.jsx      "AI 요약 / 법률 자문 아님" 고지 문구
│  └─ Loading, EmptyState, ErrorState
├─ App.jsx
└─ main.jsx
```

- 서버 호출은 `src/api/`에서만 합니다. 컴포넌트 안에서 `fetch`를 직접 쓰지 않습니다.
- 비교 바구니(선택한 법안 2건)는 검색 화면과 비교 화면이 같이 쓰므로 상위(예: Context)에서 관리합니다.

## 10. 개발 규칙

### 브랜치와 PR

```bash
git switch main
git pull
git switch -c feature/search-page      # 작업 단위별 브랜치
# 작업 후
git add .
git commit -m "feat: 검색 화면 추가"
git push -u origin feature/search-page
```

- `main`에 직접 푸시하지 않고, **브랜치 → PR → 팀원 확인 → Merge** 순서로 합니다.
- PR 전에 `npm run lint`와 `npm run build`를 실행해 오류가 없는지 확인합니다.
- 커밋 메시지는 `feat:`(기능), `fix:`(버그), `docs:`(문서), `chore:`(설정·정리), `style:`(화면 스타일)로 시작합니다.
- 브랜치 이름은 `feature/기능이름`, `fix/버그이름` 형식을 씁니다.

### 올리면 안 되는 것

- `.env`, 인증키, API 키
- `node_modules/`
- `.csv` 등 수집 데이터 파일

## 12. 알아둘 점

- 데이터는 열린국회정보의 **22대 발의법률안**입니다. 발의안일 뿐 통과 여부는 처리 상태를 따릅니다.
- AI 요약과 비교는 서버의 AI가 만든 결과라서 **틀릴 수 있습니다.** 원문 링크를 항상 함께 제공합니다.
- 검색은 서버의 검색 방식에 따라 결과가 달라집니다. 검색 품질 문제는 BE 담당과 함께 확인합니다.
