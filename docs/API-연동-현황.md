# API 연동 현황

2026-11-18 FE를 Railway 배포 서버의 실제 OpenAPI에 맞춰 연결했다. 검색은 정상 동작한다. AI 요약·비교는 백엔드의 AI 인증 오류로 성공 응답을 확인하지 못했다.

## 프론트 변경

- `/search?query=...&limit=20`: 대문자 응답 필드를 카드 형식으로 변환, 서버 정렬 유지, 준비 중·빈 결과·실패 구분, 검색 전환 시 이전 요청 취소.
- `/summary?bill_no=...`: 버튼을 누른 법안만 요청. 성공·진행 중 요청 공유, 실패 재시도. 검색·저장·비교 화면에서 같은 캐시 사용.
- GET `/compare?a_bill_no=...&b_bill_no=...`: 같은 주제의 A/B 차이를 행별로 나란히 표시. 순서별 캐시, 공유 URL 직접 진입, 오류·재시도 지원.
- 개발·preview 프록시: FE `/api/*`에서 `/api`를 제거해 Railway `/*`로 전달.
- 국회 원문 `SUMMARY`와 AI 요약을 구분. 원문은 접어서 표시. 없는 위원회·발의일·링크·매칭 키워드는 생성하지 않음.
- 기존 예시 법안의 localStorage는 보존하고 실제 저장 목록은 `beopan-itda:saved-bills:v2`에 보관.

## 실제 서버 확인

| 요청 | 결과 |
|---|---|
| GET `/search?query=소방&limit=20` | HTTP 200, `preprocess: true`, 20건 표시 |
| GET `/summary?bill_no=2222766` | HTTP 502, 내부 AI 인증 401 오류 |
| GET `/compare?a_bill_no=2222766&b_bill_no=2222550` | HTTP 502, 내부 AI 인증 401 오류 |

두 AI API의 상세 오류에는 `authentication_error - Invalid API key`가 포함되었다. FE 요청은 BE까지 도달했으며, AI 서비스 인증 설정을 BE에서 확인해야 한다. 키 값은 FE에 넣지 않는다.

localhost Origin으로 받은 검색 응답에는 `Access-Control-Allow-Origin`이 없었다. 로컬 개발·preview에서는 프록시로 동작한다. 정적 배포 시 호스팅 프록시를 구성하거나 BE에 FE 배포 도메인의 CORS를 허용해야 한다.

## 검증 범위

- `npm test`: 요청 형식·필드 변환·원문과 AI 요약 구분·폐기 상태·캐시·실패 재시도·오류·시간 초과·취소 테스트.
- `npm run lint`, `npm run build`.
- 실제 브라우저: 실제 검색 20건, 요약 자동 호출 없음, 최대 두 법안 선택, 실제 AI 실패 안내와 재시도.
- 명세 형태의 테스트 응답으로 요약·비교 성공 화면, 요약 캐시 재사용, 공유 URL 직접 진입, 빈 입력·준비 중·빈 결과·검색 실패·동일 검색어 재시도 확인.
- 360px 검색·비교 화면을 캡처해 확인하고 가로 넘침 없음 검증. 브라우저 JavaScript 오류 없음.
- AI 요약·비교의 **실제 성공 응답**은 BE 인증 오류 수정 후 다시 확인해야 한다.

## 백엔드 전달 내용

> 명세 기준으로 FE 검색·요약·비교 연동을 완료했습니다. 검색은 정상인데 `/summary`와 `/compare`가 HTTP 502를 반환하고, 상세 메시지에 AI 요청의 401 `authentication_error - Invalid API key`가 나옵니다. Railway의 AI 서비스 키와 인증 설정 확인 부탁드립니다. 수정되면 실제 성공 응답을 다시 확인하겠습니다. 검색 응답에 위원회·발의일·원문 상세 링크·매칭 키워드 추가와, 배포 시 FE 도메인 CORS 허용도 확인 부탁드립니다.

추가 협의: PROC_RESULT 처리 결과 변환 확정, 공유 비교 링크용 법안 상세 조회 API 또는 비교 응답에 이름·메타 정보 추가. 공통점·유사도·종합 비교 요약은 현재 응답에 없어서 표시하지 않는다.
